# 준지도 객체 탐지의 클래스별 임계값 갱신

논문 「준지도 객체 탐지에서 클래스별 임계값 갱신을 통한 의사 레이블 붕괴 방지」의 실험 코드와 결과입니다.
COCO에서 YOLOv8s를 처음부터(scratch) 학습하고, 의사 레이블링을 18라운드 반복하며 신뢰도 임계값 설계(전역 고정 / 클래스별 고정 / 클래스별 갱신)에 따른 정밀도·재현율 붕괴를 비교합니다.

## 폴더 구성

```
src/        실험 코드 4개 (논문 실험에 쓴 코드 그대로)
scripts/    실행 스크립트, 표·그림 생성 스크립트
results/    실험별 결과 CSV (가중치 제외) — 논문 숫자는 모두 여기서 다시 계산됨
docs/       코드_설명.md, 결과_재현.md, 실험_기록.md
```

## 주요 결과

같은 범위에서 클래스별 임계값을 고정(B)했을 때와 3라운드마다 갱신(C)했을 때의 비교입니다. ρ_P(마지막 라운드 정밀도 ÷ 1라운드 정밀도)가 0.9 미만이면 정밀도 붕괴로 봅니다.

| 범위 | 고정 ρ_P | 갱신 ρ_P | 고정 최고 mAP | 갱신 최고 mAP |
|---|---|---|---|---|
| 없음 | **0.82** (붕괴) | 0.92 | 0.2004 | 0.2051 |
| 0.3~0.5 | 0.96 | 1.02 | 0.2091 | **0.2148** |
| 0.2~0.85 | **0.88** (붕괴) | 0.94 | 0.2007 | 0.2107 |

- 고정 임계값은 범위가 없거나 넓으면 정밀도가 붕괴했고, 갱신 임계값은 세 범위 모두 붕괴하지 않았습니다.
- 갱신 0.3~0.5의 최고 mAP(0.2148)는 정답으로 고른 최적 전역 임계값 0.4(0.2154)와 0.0006 차이입니다.
- 실험별 값은 `docs/결과_재현.md`에 있습니다.

## 환경

- GPU: NVIDIA RTX 3070 (8GB)
- Python 3.13, PyTorch 2.6.0 (CUDA 12.4), Ultralytics 8.4.51

```bash
pip install torch==2.6.0 torchvision --index-url https://download.pytorch.org/whl/cu124
pip install -r requirements.txt
```

## 데이터 준비

COCO 2017을 아래 구조로 둡니다. 기본 경로는 저장소 아래 `coco/`이고, 다른 곳에 있으면 스크립트 인자로 경로를 넘깁니다.

```
coco/
├── train2017/                          # 이미지 118,287장
├── val2017/                            # 이미지 5,000장
└── annotations/
    ├── instances_train2017.json
    └── instances_val2017.json
```

## 실행

```bash
# 1) 부분집합 분할(20개, seed 42) + 초기 레이블러 학습 (YOLOv8s scratch, 최대 200 에포크)
bash scripts/run_initial.sh /path/to/coco

# 2) 실험 실행 (실험 하나에 RTX 3070 기준 약 1~1.5일)
bash scripts/run_experiment.sh C_refresh_0.3-0.5 /path/to/coco   # 제안 방법
bash scripts/run_experiment.sh B_fixed_norange   /path/to/coco
bash scripts/run_experiment.sh A_global_0.4      /path/to/coco

# 학습 없이 준비 단계(설정 적용, 임계값 산정)만 확인할 때
bash scripts/run_experiment.sh C_refresh_0.3-0.5 /path/to/coco --dry-run --eval-max-images 20
```

| 실험이름 | 논문 | 내용 |
|---|---|---|
| `A_global_0.1` ~ `A_global_0.7` | 표 3, 그림 6 | 모든 클래스에 같은 임계값을 고정 |
| `B_fixed_norange`, `B_fixed_0.3-0.5`, `B_fixed_0.2-0.85` | 표 5, 그림 7 | 클래스별 임계값을 보정용 데이터셋에서 한 번 정해 고정 |
| `C_refresh_norange`, `C_refresh_0.3-0.5`, `C_refresh_0.2-0.85` | 표 6, 그림 8 | 클래스별 임계값을 3라운드마다 다시 산정 (제안 방법) |

결과는 `runs/<실험이름>/p2_1_output/` 또는 `runs/<실험이름>/p2_2_output/`에 생기고, `pseudo_round_results.csv`가 라운드별 검증 지표입니다.

## 논문 표·그림 다시 만들기

```bash
python scripts/make_tables_figures.py --results results --out paper_outputs
```

표 3, 5, 6, 7과 그림 6, 7, 8을 `paper_outputs/`에 만듭니다. 새로 돌린 결과로 만들려면 각 실험의 `p2_*_output/*.csv`를 `results/<실험이름>/`에 복사한 뒤 실행합니다.

## 주의

- 같은 장비에서는 결과가 재현되지만(Ultralytics가 데이터로더 시드를 고정), GPU가 다르면 라운드별 mAP가 0.003 정도 달라질 수 있습니다.
- 실험 설정은 `src/p0_common_api.py`의 값으로 정해지며, `run_experiment.sh`가 실험마다 4개 값(fallback, 하한, 상한, 갱신 주기)만 바꾼 복사본을 만들어 실행합니다.
- 코드 구조와 설정 설명은 `docs/코드_설명.md`, 논문 표마다 실행 명령과 기대값은 `docs/결과_재현.md`에 있습니다.
